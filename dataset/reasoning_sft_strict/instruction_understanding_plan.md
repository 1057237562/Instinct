# 当前检查点的指令理解调优修订

用户明确首要问题是没有理解要求。此前课程能检验答案正确性，但固定模板、数字变体和数学任务不能充分覆盖这一目标。本文件是修订设计，尚未声称已构建新的专项数据集或完成专项模型评测。

## 本地证据与边界

- HumanEval 诊断中的去重与只保留单次出现、普通乘积与个位乘积混淆，支持相近任务语义辨析薄弱的判断。
- GSM8K 诊断中将故事里的下载理解为要求助手实际下载，支持任务意图与材料内容混淆的判断。
- GSM8K 严格终答格式全部失败，同时存在关系及算术错误。格式失败不能单独证明所有题目都没有理解。
- 尚未进行 chat template、thinking 开关及固定解码设置的对照，不能断言原因仅在数据。

## 专项数据应该监督什么

1. 同一材料、不同指令：抽取与改写、计数与列举、排序与保留原序、去重与只留单次出现。关键指令改变时，参考答案必须实际不同。
2. 同一任务、不同表达：正式表达、自然口语、否定限定、简短省略和带干扰材料的表达。评估留出措辞与模板，不能仅换数字划分。
3. 明确对象与约束：谁的数量、处理哪个字段、只返回哪些内容、不要包含哪些项，以及同时满足两三个条件。
4. 多轮要求修订：用户改变排序、字段或输出形式后，回答遵循当前要求；无冲突的前文条件仍保留。
5. 简短完成任务：多数答案直接交付结果；少量任务显式要求提取操作、对象和限制，以检查任务解析。不要把所有回答强制变成长解释。

素材先采用不依赖冷门知识或复杂算术的内容，让错误更容易归因于指令处理。现有数学课程仅作为辅助保留候选，不先指定没有实验依据的最佳混合比例。

## 全量验收要求

- 每条训练对话检查语义标签、条件满足情况与格式；JSON 合法、能编译或算式正确都不等于理解了指令。
- 对照组逐组检验：关键要求变化确实改变预期答案；保留顺序、重复次数、排除条件等逐项验证。
- 开放式回答若只能自动验格式，必须明确标为语义未验收，不进入全量验收集。人工或代理的语义审查记录需覆盖每条，不能用抽样结论替代。
- 训练与评估按材料来源及表达模板分组隔离；单独报告单项约束通过率、所有约束同时通过率、对照指令双正确率，以及多轮修订成功率。
- IFEval 的可验证指令方法可用于格式约束检查，但不能替代任务语义检查；基准题目不作为训练材料。来源：https://arxiv.org/abs/2311.07911

## 实验顺序

先用用户实际失败指令及独立构建的对照题建立当前权重基线，检查模板和推理设置，再小规模继续 SFT。优先观察未见表达下的任务完成率，同时监测数学、代码及普通对话保留。是否采用 CPT 或 RL 留给这些结果决定，当前证据不足以支持直接切换训练阶段。

现有 run_reasoning_sft.py 仍训练原来的基础课程，未自动切换为这里描述的专项数据；本次没有启动训练。
